📋 Executive Summary

Sudanile Kitchen is a recipe-sharing platform built to preserve South Sudanese culinary heritage. The project has a strong functional core: the Django REST backend, custom admin interface, Firebase + JWT authentication, and the Flutter app all work end-to-end for the primary user loop (browse → detail → favorite / review / submit).

The audit found no architectural blockers, but several claimed-but-absent features (rate limiting, server-side email verification, password reset endpoints, API documentation) and one guaranteed runtime failure (account deletion calls a backend endpoint that does not exist). Documentation in mobile/STATUS_REPORT.md is stale relative to the current code.

🛡️ Security Findings

High
  • CORS_ALLOW_ALL_ORIGINS = True combined with CORS_ALLOW_CREDENTIALS = True (settings.py:115-116) — effectively opens authenticated endpoints to any origin.
  • DEBUG defaults to True and ALLOWED_HOSTS defaults to '*' (settings.py:10-11) — dangerous if env vars are unset in prod.
  • Real Gmail app password + Django SECRET_KEY sitting in backend/.env (untracked, but rotate before any deployment if it has been shared).
  • No brute-force throttling on login/register (rate limiting entirely absent).
Medium / low
  • Registration hard-restricted to @gmail.com — blocks non-Gmail users entirely.
  • Two divergent requirements.txt files (root vs. backend/) with different pin sets; README instructions are ambiguous about which one to use.
  • submissions/signals.py prints emails to console instead of logging.
  • Migrations generated under Django 6.0.7 but pinned to 4.2.16.
  • scripts/pre-commit-secrets.sh exists but isn't installed as a git hook.
